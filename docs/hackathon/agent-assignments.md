Contract: deterministic calculation snapshots persist actual method parameters, immutable method descriptions, daily directed aggregates and source hashes. Review tools resolve a snapshot hash, never the server's active selection. IDs remain decimal int64 strings; directed amounts are observed KZT; dates have day precision, with no intraday ordering or fund-lineage inference. Discovery covers all supplied nodes and reports scanned/found/examined separately, with bounded diverse candidate examination. Reviews and briefs are separate from calculation exports. Legacy snapshots remain readable; unavailable temporal evidence is explicit and requires a new calculation rather than silently recomputing a saved result.

HTTP contract: `GET /api/analyses/<id>/reviews` returns availability, snapshot identity, reviews and briefs; `POST` starts or reuses a compatible completed review with a required snapshot identity and locale. `GET /api/analyses/<id>/reviews/<review-id>` retrieves progress, suggestions, executed checks and coverage; `POST .../<review-id>/cancel` cancels; `POST .../<review-id>/follow-up` updates a suggestion's boolean marker; `POST .../<review-id>/briefs` saves a brief built from validated findings; `GET .../<review-id>/evidence/<evidence-id>` retrieves immutable evidence. The same-origin loopback guard applies to mutations. Invalid body/reference is 400, missing record 404, incompatible snapshot/state 409, damaged saved data 422, disabled AI 503, and persistence failure 500. Job states are queued/running/completed/partial/cancelled/failed/interrupted; budgets never imply exhaustive examination.

The Responses transport uses Python's standard library and strict JSON schemas; no runtime dependency is added. Calculations, tools, schemas, agent orchestration, transport and storage have distinct modules. Acceptance covers independent synthetic calculations, all-node and component coverage, tool schemas/pagination, rejected claims, method changes, review identity across page switches, budgets/cancellation/failure/restart, saved briefs and the real browser journey. Live synthetic evaluations are explicitly invoked separately and require backend credentials, a selected model and configured prices/budget; mocked checks do not establish model quality.

## Agreed local contract

- Python CLI reads the three documented Parquet files, validates before calculating, writes the three official CSV schemas and a deterministic dashboard JSON. A separate run manifest records hashes, versions, hardware and timing.
- Python standard-library HTTP server binds only to `127.0.0.1`. `GET /api/overview` returns counts, cluster summaries and ranked accounts; `GET /api/account?gid=<exact decimal int64>` returns measured features, role rules, priority contributions, all incident directed edges and a bounded one-hop graph. `GET /api/graph?gid=<id>&hops=1|2&revision=<active revision>` returns up to 50 accounts (center included), all directed edges between them, hop distances, eligible/omitted counts and the limit. Neighbors in either direction define distance; breadth-first selection breaks ties by exact numeric gid. IDs remain decimal strings. Invalid queries return 400, missing IDs/routes 404, stale revisions 409 and no active analysis 503.
- `POST /api/analysis` accepts exactly three multipart fields named `nodes`, `edges`, `transactions`, with corresponding `.parquet` filenames, at most 64 MiB total including framing. Host and Origin must match the loopback server. It returns 202 after receipt; one job runs at a time (409 otherwise). `GET /api/status` reports receiving/validating/analyzing/exporting/succeeded/failed, an error/message and active revision. All parsing, validation, analysis, exports and manifest creation finish in a separate local directory before a single locked active-snapshot swap. Failed jobs preserve active API data and download bytes. Successful upload inputs/outputs remain under `<out>/uploads/<run-id>/{input,output}` for reproduction; startup outputs are preserved. No database or external service is involved.
- CSV uses UTF-8, LF, exact decimal int64 IDs, fixed six-decimal scores and JSON arrays of decimal strings for `top_gids`. Amounts are observed KZT; dates have day precision with no timezone. Graph direction is payer → recipient; all supplied nodes are added first.
- pandas and PyArrow load/validate Parquet; NetworkX builds the directed graph and seeded weighted Louvain communities. Exact dependency pins are in the two requirements files; Playwright is test-only. No new Node dependencies, external assets or runtime network services.
- Acceptance: strict schemas and reconciliation; synthetic motifs and boundary counterexamples; all-node coverage including isolates; at least 20 ranked official accounts; byte-identical repeated CSV/JSON output; timed official run below 300 seconds; real HTTP and automated browser journey; existing root typecheck/tests/build. Remote CI remains a gap until a user-authorized push.

- Local setup contract (ENG-03): `.python-version` pins the existing verified interpreter; setup creates or checks `.venv`, installs the unchanged exact requirements and verifies dependencies. Launch validates runtime/package versions without installing anything. CI uses the same setup and separate synthetic Python/browser checks. No application API or data semantics change.
